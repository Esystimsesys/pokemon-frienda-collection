# コミットメッセージを書く

書式は [Conventional Commits 1.0.0](https://www.conventionalcommits.org/ja/v1.0.0/)。
要約と本文の作法は Git 自身の指針（[SubmittingPatches](https://git-scm.com/docs/SubmittingPatches)）に従う。
判断に迷ったら `docs/commit-messages.md` を読む（型・範囲の一覧と、なぜそう決めたかが書いてある）。

## 手順

1. **コミットしてよいか確かめる。** 使う人が「コミットして」と言っていなければ、
   ここで止まる。変更内容を報告するだけにする。勝手にコミットしない。push はなおさら。
2. `git status --short` と `git diff`（ステージ済みなら `--staged`）で、
   何が変わったかを自分の目で見る。
3. **1コミット1目的**になっているか見る。混ざっていたら分けることを提案する。
   - 「データの作り直し」と「コードの修正」は分ける
   - 生成物は生成元スクリプトの変更と同じコミットに入れる
     （例: `scripts/ocr/export_type_icons.py` と `assets/types/*.png` は一緒に）
4. 型と範囲を決めて、下の書式で書く。
5. 後方互換を壊すなら `!` か `BREAKING CHANGE:` を必ず付ける（下記）。
6. `Co-Authored-By:` は**付けない**。Claude が書いたコミットでも付けない。

## 書式

```text
<型>(<範囲>): <要約>

<本文>

<フッター>
```

範囲・本文・フッターは省略してよい。要約だけの1行コミットでもよい。
日本語で書く（型と範囲だけ英字）。

## 型

| 型 | 使うとき |
|---|---|
| `feat` | 機能の追加・変更。画面の見た目や動きが変わるもの |
| `fix` | 不具合の修正 |
| `data` | `src/data/*.json` や `assets/types/*.png` の作り直し |
| `docs` | 文書だけ。README・`docs/`・コードのコメント |
| `refactor` | 動きを変えない作り直し |
| `perf` | 速さ・軽さの改善 |
| `build` | ビルドと依存関係。`package.json`・Expo の設定 |
| `ci` | GitHub Actions（`.github/workflows/`） |
| `chore` | 上記に入らないもの。`.gitignore` など |

`style` は使わない。Conventional Commits ではコードの整形を指す型で、
画面の見た目の変更（`feat` / `fix`）とまちがえやすいため外してある。

## 範囲

省略可。迷ったら付けない。
`list` / `detail` / `party` / `trainers` / `record`（各画面）、
`search` / `filter` / `collection`、`sw` / `pwa`、`ocr` / `icons` / `scripts`。

## 要約（1行目）

- 50文字以内をめやす
- **言い切りで書く**。「直す」「そろえる」「追加する」。「直した」「直します」は使わない
- 末尾に句点を付けない
- 何を変えたかを書く。ファイル名の羅列にしない

## 本文

- 要約との間に空行を1行
- 1行72文字くらいで折り返す
- **「なぜ」を書く**。「どうやって」はコードを見れば分かる
  1. 変える前は何が問題なのか（現在形で書く）
  2. 変えたあとがなぜ良いのか
  3. 検討して採らなかった案と、その理由
- 料金・仕様など裏付けが要ることは、参照した一次情報のURLを残す

## 後方互換を壊す変更

このアプリで該当するのは、**所持データ（localStorage）の形が変わって、
今まで登録したぶんが読めなくなる**変更。子供の記録が消えるので必ず明示する。

```text
feat(collection)!: 所持枚数の保存形式を変える

BREAKING CHANGE: 旧形式のデータは読めなくなる。移行のしかたは
src/lib/collection.ts の読み込み側に書いた。
```

## 例

```text
feat(search): ひらがなで打ってもカタカナの名前に当たるようにする

NFKC でそろえてから ひらがな→カタカナ に寄せる。ポケモンの名前は
全部カタカナなので、寄せる向きはこちらが自然。
半角カタカナ（ﾋﾟｶﾁｭｳ）も NFKC で拾える。
```

```text
fix(icons): タイプのマークの位置と大きさをそろえる

1枚のカードから位置合わせなしに切り出していたため、18個で大きさも
余白も中心もずれている。公式サイトにマークだけの画像は無いので、
いちばん大きく写っている裏面のわざ欄1行目（50px）から作り、
25枚を位置合わせして中央値で重ねる。
```

```text
docs: README を開発者向けの漢字表記に直す
```
